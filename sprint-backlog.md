
# GoClean — Sprint Backlog

## 1. Introduction

The sprint backlog is a collection of features and tasks selected for a sprint. It helps the team organise the work that needs to be completed during a development period and monitor progress towards the sprint goal.

For GoClean, our Trello board separates planned features into Sprint 1, Sprint 2,Sprint 3 till Sprint 16. These lists organise the proposed customer journey, from accessing the platform to placing and tracking laundry orders and managing customer accounts.

The sprint backlog describes the work planned for the proposed GoClean platform. Features listed in a sprint are not necessarily completed, implemented or tested.

## 2. Sprint Goals and Planned Work

### Sprint 1: Customer Access and Landing Page

**Sprint goal:** Organise the main entry point to GoClean and the features customers need to access the proposed platform.

| Feature | Planned tasks |
|---|---|
| Welcome/Landing Screen | Design the welcome screen and introduce the GoClean service. |
| Home Page | Organise the main navigation and display key service information. |
| Registration Page | Plan the registration form and identify the information needed to create an account. |
| Login Page | Design the login screen, plan secure credential storage, build the login API and test error handling. |

**Progress evidence:**

The Login Page card on our Trello board contains five subtasks and displays 100% checklist completion. This provides evidence that the subtasks were marked as complete on Trello. Further implementation and testing evidence would be needed to confirm that the login feature works as intended.

### Sprint 2: Laundry Orders and Tracking

**Sprint goal:** Organise the features required for customers to request laundry collection and follow the progress of their orders.

| Feature | Planned tasks |
|---|---|
| Order Page (Booking) | Identify the details customers need to provide when booking laundry collection and plan the booking process. |
| Order Confirmation | Plan how customers will receive confirmation after submitting an order. |
| Order Tracking | Identify the order progress information that should be displayed to customers. |
| Order History | Plan how customers can review their previous orders. |

These features support the main GoClean service journey. The booking feature is particularly important because it would allow customers to arrange laundry collection through the proposed platform.

The detailed tasks should be reviewed and updated by the team in Trello as work progresses. The presence of these features in Sprint 2 indicates planned work and does not, by itself, establish that the features have been implemented.

### Sprint 3: Account Management and Supporting Features

**Sprint goal:** Plan additional features that support customer account management and the proposed pickup and delivery process.

| Feature | Planned tasks |
|---|---|
| User Profile/Settings | Identify the customer information and settings that should be available. |
| Notifications | Identify important order updates that customers may need to receive. |
| Driver Assignment | Plan how deliveries could be assigned and organised. |
| Payments | Identify the payment requirements for the proposed service. |

These items extend the proposed customer journey and support the operational needs of the laundry service. For example, notifications could keep customers informed about order progress, while driver assignment would help organise the proposed delivery process.

The inclusion of these features in a sprint list indicates planned work rather than confirmed implementation or testing.

## 3. Task Organisation and Progress Tracking

Our team uses Trello to organise features and tasks. The separate sprint lists help make planned work visible and allow team members to review what needs attention.

Breaking features into smaller tasks makes work easier to understand, assign and monitor. Checklists can also show progress on individual cards. For example, the Login Page card has five subtasks marked as complete.

To improve progress tracking, the team should:

- Keep each Trello card updated.
- Assign clear responsibilities to tasks.
- Identify unfinished work and potential delays.
- Communicate difficulties and dependencies between features.
- Review progress against the sprint goals.
- Distinguish checklist completion from verified implementation and testing.
- Record changes to sprint plans so that team members understand the current priorities.

These practices would help the team maintain an accurate record of progress and identify work that still requires attention.

## 4. Challenges and Areas for Improvement

One area for improvement is ensuring that tasks have clear owners and realistic completion targets. The team should also review dependencies between features. For example, the order booking process may depend on customer account access and the information required to create an order.

Another challenge is ensuring that progress records accurately reflect the work completed. A checklist marked as complete is useful for tracking tasks, but it should be supported by appropriate implementation or testing evidence when the team needs to demonstrate that a feature works correctly.

Regular updates would help the team identify delays earlier and adjust plans when necessary. Any changes to the sprint backlog should be discussed and recorded so that team members share an understanding of the work.

## 5. Personal Reflection

Working with a sprint backlog has helped me understand how Agile development divides a larger project into smaller, more manageable stages. For GoClean, the sprint lists group related features together, beginning with customer access, moving to ordering and tracking, and then covering additional account and service features.

I have also learned that having a feature listed in a sprint does not mean that it has been completed. Progress needs to be supported by updated tasks and appropriate evidence from the team's project board. The Login Page checklist is an example of evidence that can be used to show recorded progress on an individual feature.

In future sprint planning, I would encourage the team to assign clear responsibilities, agree on achievable targets and update Trello consistently. I would also encourage the team to record testing outcomes so that planned tasks, completed checklists and verified functionality can be distinguished clearly.

Overall, this activity helped me understand how sprint planning, task organisation and progress tracking contribute to teamwork and the management of an Agile project.
